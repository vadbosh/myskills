# Как каждая IDE хранит состояние

[English version](how-it-works.en.md) · [README](../README.RU.md)

`myskill` пишет ту настройку, которую IDE и так читает. Здесь перечислены эти
настройки, имя скила, которое в них ждёт каждая IDE, и случаи, когда одной
настройки мало.

Состояние хранится в обычных файлах, поэтому `myskill` работает без
запущенной IDE: его вызывают из любого терминала. Скил — лишь ещё один способ запустить ту же
команду.

## Claude Code

| Состояние | Что пишет `myskill` |
|---|---|
| `off` | `"skillOverrides": {"<name>": "off"}` в `~/.claude/settings.json` |
| `manual` | `"skillOverrides": {"<name>": "user-invocable-only"}` |
| `on` | удаляет запись |

Имя — каталог скила. У скила плагина — `<plugin>:<directory>`.

**Скил плагина.** Для скила плагина Claude Code `skillOverrides` не применяет.
Так написано в документации, и так вышло на проверке: скил плагина с записью
`"off"` загрузился в новой сессии. Поэтому `off` ещё и
переименовывает `SKILL.md` в текущей установке плагина в `SKILL.md.myskill-off`,
а файл команды плагина — в `<name>.md.myskill-off`. Запись в `skillOverrides`
остаётся: по ней `apply` знает, что выключено. `manual` у скила плагина нет:
`manual` его выключает.

**После обновления плагина** в новой установке снова лежит `SKILL.md`. Хук
`SessionStart` `myskill apply` переименовывает его ещё раз.

## Codex

| Состояние | Что пишет `myskill` |
|---|---|
| `off` | `[[skills.config]]` с `name = "<name>"` и `enabled = false` в `~/.codex/config.toml` |
| `manual` | `<skill>/agents/openai.yaml` с `allow_implicit_invocation: false` |
| `on` | удаляет и то, и другое |

Имя — поле `name:` во frontmatter скила. У скила плагина — `<plugin>:<name>`.
На проверке запись под голым именем оставила скил плагина видимым.

**Файл `manual` лежит в каталоге скила.** Установщик может копировать этот
каталог из исходного репозитория, и следующая копия теряет файлы, которых в
источнике нет. Поэтому `manual` пишет файл и в источник:
`$MYSKILL_CANON/skills/<skill>/`, по умолчанию `~/ai-config-source/skills/<skill>/`.
Там его надо закоммитить. Скил, чей источник — другой репозиторий, получает
файл только в установленном каталоге. Когда его установщик отработает снова,
`myskill apply` вернёт файл на место.

В Codex у скила плагина тоже нет `manual`: `manual` его выключает.

**Плагины удалённого маркетплейса** включаются в аккаунте, а не в
`config.toml`. `myskill` спрашивает `codex plugin list` и хранит ответ в
`~/.cache/myskill/`, пока не изменятся `config.toml` или кэш плагинов.

## Opencode

| Состояние | Что пишет `myskill` |
|---|---|
| `manual` и `off` | `"permission": {"skill": {"<name>": "deny"}}` в `~/.config/opencode/opencode.json` |
| `on` | удаляет запись |

Имя — поле `name:` во frontmatter. Запрещённый скил скрыт от модели, но
`/skills` его всё равно запускает. Поэтому `off` в Opencode нет: `myskill list`
показывает запрещённый скил как `manual`.

Opencode читает ещё `~/.claude/skills` и `~/.agents/skills`, если не задана
`OPENCODE_DISABLE_CLAUDE_CODE_SKILLS`. `myskill` учитывает и эти скилы.

Какие скилы npm- или git-плагина Opencode загружает, знает только сам
Opencode. `myskill` спрашивает `opencode debug skill` — это около 8 секунд — и
хранит ответ в `~/.cache/myskill/`, пока не изменится `opencode.json`.

Команду Opencode модель не видит никогда. Для неё `myskill off` ничего не пишет
и объясняет почему.

## Что делает `apply`

`myskill apply` запускается из хука `SessionStart` в Claude Code и Codex. Если
делать нечего, он ничего не печатает.

1. Снова переименовывает `SKILL.md` скила плагина, у которого в
   `skillOverrides` стоит `off`, если обновление плагина вернуло файл.
2. Возвращает `agents/openai.yaml` Codex, который удалил установщик.
3. Один раз при старте сессии называет скилы, которых ещё нет в
   `requires.json`.

## Что находит `deps`

`myskill deps <name>` ищет имя в хуках, правилах и других скилах и печатает
каждую найденную строку. Он находит имя, а не намерение: правило, которое
только предлагает `/review`, считается зависимостью от `review`. Прочитайте эти
строки, прежде чем добавлять `--force`.

## Как проверялся `list`

2026-10-08 вывод `myskill list` сверили с отчётом каждой IDE:
`codex debug prompt-input`, `opencode debug skill` и списком скилов Claude Code. Они
совпали, кроме 12 встроенных скилов Claude Code, которых нет ни в одном файле.
